# ADR-005: Proposed qualification-contract reconciliation and physical-gate crosswalk

**Status:** Draft proposal / NON-NORMATIVE. Not an active oracle or session authorization.
**Owner:** Daniel
**Source:** [ADR-005](../adr/adr-005-physical-product-observation-boundary.md), [Q1–Q37 rationale](../adr/adr-005-design-decision-log.md), Issue #68
**Source operation tables:** [Android job lifecycle](android-job-lifecycle.md), AND-04 = 31 operations, AND-05 = 45 operations
**Preparation date:** 2026-11-14

## 1. Change-control boundary

The owner accepted the architectural design choices Q1–Q36 and closed the design tree at Q37. This document identifies the required *future amendments* to active qualification/specification contracts; it is not itself permission to change those contracts, run the observer, operate a device, or declare physical acceptance. **Keep qualification contract v5, capability v4, oracle v9, frozen AND-04 31/AND-05 45 operation orders and deadlines, and existing artifact pins unchanged** until separately reviewed. Do not reinterpret an old assertion to accept a new source without explicit versioned authorization. Incompatible historical records retain their original pins.

The Stage A/B NO-GO evidence remains historically correct for the then-permitted mechanisms. Q8's proposed socket is unimplemented and requires target-specific feasibility. The new G3/G4/G5 definitions are owner-approved design labels, not evidence of passed gates.

The protocol's numeric limits, storage bounds, exact wire framing, OS command allowlist and actual peer UID are **engineering investigations**, not owner-approved values. **Q18 already selected the visible Advanced/Diagnostics default-OFF toggle as the activation mechanism** (and Q12 selected persistent enablement through restart). Remaining engineering evidence concerns actual listener readiness, startup non-interference, verifying enabled/disabled state, failure-safe cleanup and documented restoration steps—not re-selecting a hidden/ADB activation method. These checks require separate session/device authorization. Measure/prove these before proposing final contract fields. Library mutation races and process loss invalidate an observation (Q15, Q34); no silent restart. Complete Jobs history uses one bounded coherent read (Q6/Q16), not offset paging.

## 3. Gate definitions and evidence classes

| Proposed gate | Scope | Essential evidence |
| --- | --- | --- |
| **G3 — admission and baseline** | Before AND-04/AND-05 effectful operations | Exact target and qualification signed APK/base/splits/signer, OS readiness, authorized installed fixture-only/no-reset state, all retained refresh history, committed Library baseline, diagnostics enabled during preparation, observer readiness and pending-cleanup safety |
| **G4 — AND-04** | Original 31-operation background/return sequence | Active refresh and typed parent/child progress, complete state, background OS checkpoint, same *existing* Android task upon return, expected foreground/UI, truthful restoration and evidence |
| **G5 — AND-05** | Original 45-operation process-loss/Retry sequence | Pre-stop complete state, authorized force-stop and independent process-loss OS evidence, authorized relaunch (no same-task requirement across force-stop), durable committed membership/redirects, correct root attribution, no silent resume, at most one eligible explicit Retry, successor terminalization and cleanup |

Evidence classes: `P` = authoritative product backend read (not independent backend correctness oracle); `U` = ordinary visible Flutter/accessibility state; `O` = independent Android OS package/process/foreground/task data; `H` = admitted host action and private owner/session/fixture authority. Claims must name their actual source, not label a combined adapter as a second backend. The source fields in the crosswalk below describe a **proposed proof obligation** to be translated into versioned PAC/TAC criteria; they are not newly active acceptance oracles.

### Assertion-level crosswalk: evidence and classification

Each row names a **frozen operation and its exact deadline**, its prerequisites, the claim that must be established, the source text supporting that claim, evidence/provenance, and outcome-specific stop behavior. These are proposed *future* source substitutions, **not** changed v5/v4/v9 oracles. The source references use exact GitHub line anchors in the unchanged [active Android lifecycle contract](android-job-lifecycle.md). For every row, authoritative operation identity/order/deadline is the cited J table row; additional normative interpretation comes from the adjacent cited J paragraphs and SPEC-BE sources. Section-level rules remain controlling if a short summary omits an edge case.

Every candidate receipt must bind `H`: exact owner-approved target, package, artifact/signer, session authorization and plan/rules digest, operation grant/arguments, monotonic start/completion or timeout, sanitizer version and append-only outcome. `U`: UI capture ID, hierarchy/selected route, exact resource identity and capture time (private raw XML never retained). `P`: typed product JobRun/ScanRun/root identities, coherent GetJob or complete-history result, nonempty observer reference and read time. `V`: internal fixed query fingerprint/generation/revision, ordered first-to-terminal pages, unique GameIds, direct token-bound GetGame results and one observation attempt reference; raw cursor/token remain private to the app. `O`: independently observed package-scoped process/foreground/task identity, timestamp and command provenance, with unrelated state discarded. These are evidence **classes**, not evidence that the observer has been built. `PASSED` proves the operation's asserted behavior; `FAILED` requires a conclusively contradictory valid observation, `BLOCKED` means no trustworthy decision; unexecuted dependent operations are `NOT_RUN`, not silently passed.

#### Non-collapsible multi-assertion acceptance requirements

**AND-04-25 (§3, 60 s).** This is not merely a successful read of `GetJob`. The original parent must reach an observable terminal state within the **existing 60-second monotonic bound**; the identity/status evidence must be coherent with the matching UI. If still active when the deadline expires or the terminal result is unavailable, mark **BLOCKED**, leave **AND-04-26 through 31 NOT_RUN**, and do not extend the operation or session timeout. A conclusive different valid parent is **FAILED**. Sources: [J:L165–173](android-job-lifecycle.md#L165-L173), [J:L490](android-job-lifecycle.md#L490).

**AND-05-35 (pre-dispatch source-bound no-successor proof).** Before recording *Retry intent* or dispatching:
1. Require AND-05-27 (root recovery) and AND-05-29 (Library persistence) PASSED, plus recovered terminal source state and current Retry eligibility from AND-05-33/34; use one **fresh** coherent source-bound relation lookup.
2. Bind the exact original parent JobRunId, captured **requested/admitted/excluded** root sets, recovered terminal state, one unique source ScanRun per source-admitted root and all source `(parent JobRunId, ScanRunId, LibraryRootId)` tuples.
3. Prove there is **no** successor JobRunId, direct source/successor link, successor scope, successor requested/admitted/excluded partition, typed exclusion or successor ScanRun relation. The successor relation collection must be the **explicit empty tuple**; an unavailable `None` or omitted field is not empty evidence. Any successor metadata of uncertain identity blocks before intent/dispatch.
4. Only after those checks, perform the **one** owner-authorized Retry of the original requested root set with eligibility rechecked. A failed or uncertain effect must not be replayed. Any missing, stale, conflicting, nonempty, or unavailable precondition is **BLOCKED**, not absence; dependent work remains **NOT_RUN**. Sources: [J:L267–281](android-job-lifecycle.md#L267-L281), [J:L473](android-job-lifecycle.md#L473), [J:L505–506](android-job-lifecycle.md#L505-L506), [BE-008 §68.6](../specifications/backend/spec-be-008-rust-to-flutter-bridge-dto-contract.md#L2870-L2995), [BE-013 Retry](../specifications/backend/spec-be-013-library-source-management-scan-operations-and-source-projections.md#L790-L829).

**AND-05-36 (successor outcome and scope).** The Retry successor is a *different* JobRunId from the original; it retains the **original requested root set** but may admit a different eligible subset. The current-eligibility recheck and changed admitted/excluded partition are recorded explicitly. There must be **at least one admitted root**, exactly **one successor-owned ScanRun for each admitted root**, and a typed **SPEC-BE-013** exclusion reason for **every excluded requested root**. The source's requested/admitted/excluded partition and exact source ScanRun set must still equal their **pre-interruption captured values**. Source and successor ScanRun IDs must be **disjoint**. Missing/ambiguous partition, exclusions or relations are **BLOCKED**; proven foreign parent or ScanRun belonging to an excluded root is **FAILED**. Sources: [J:L281–291](android-job-lifecycle.md#L281-L291), [BE-013 Retry](../specifications/backend/spec-be-013-library-source-management-scan-operations-and-source-projections.md#L790-L829), [BE-008 §68.6](../specifications/backend/spec-be-008-rust-to-flutter-bridge-dto-contract.md#L2870-L2995).

**AND-05-37 (independent relationship proof).** An independently sourced `JobIdentityObservation` must verify the exact original-to-successor direct link, requested scope, both admitted/excluded partitions, typed exclusion reasons and complete source/successor ScanRun-to-root ownership; IDs remain disjoint and unambiguous. The separately captured `RefreshDetailObservation` must identify the expected successor parent and original source. Missing, incomplete or unbinding independent identity evidence is **BLOCKED**, as is malformed/missing detail identity; a **different valid** parent/source is **FAILED**. Neither list order, display labels nor timing supplies the link. No second Retry. Sources: [J:L267–292](android-job-lifecycle.md#L267-L292), [J:L324–335](android-job-lifecycle.md#L324-L335), [J:L502–504](android-job-lifecycle.md#L502-L504).

**AND-05-45 (two independent terminal/outcome claims, 60 s).** Record **both**:
1. Terminal observation: independently bound **exact successor** becomes terminal during the **fixed 60-second window**, with the **qualification package continuously foreground for the required observation**. Prove exact successor JobRunId, nonempty observer provenance, matching UI detail and OS foreground evidence. Missing/malformed ID, unavailable foreground evidence or `Active` at the deadline is **BLOCKED**; different *valid* successor identity is **FAILED**. A supported terminal state may satisfy this assertion even when Retry success fails.
2. Retry success: apply **pinned** outcome policy to the same exact successor, independent of terminal timing. `Completed` = **PASSED**. `CompletedWithIssues` = **BLOCKED** without immutable owner-approved acceptance. `Failed`, `Cancelled`, `Abandoned` and **`Interrupted`** = **FAILED** Retry-success assertion even when terminal observation passed. No automatic second Retry; owner recovery. In contrast, `Interrupted` on the *original post-stop parent* at AND-05-33 is a failed recovery-consistency case, not a successful Retry. Sources: [J:L313–331](android-job-lifecycle.md#L313-L331), [J:L474–480](android-job-lifecycle.md#L474-L480), [J:L509–514](android-job-lifecycle.md#L509-L514).

## 5. Runtime and privacy invariants

1. Trust owner-controlled ADB host with existing owner/session admission; require target-qualified peer UID, allowlisted read operations and bounded outputs, but no new PKI. Unverified UID/forwarding access => NO-GO for that mechanism, not authority to downgrade.
2. Ship identical observer implementation in qualification and distributable Release; **Q18 explicitly selects a visible Advanced/Diagnostics default-OFF toggle** for owner-authorized preparation, and **Q12** requires enablement to persist across process death/relaunch. Remaining readiness and cleanup engineering must prove listener ON/OFF response, absence of observer cold-start, disabling verification, and truthful incomplete-cleanup reporting—not reopen the selected activation mechanism. Listener exists only in a live application process and must not cold-start or keep it alive.
3. Serialized observer operations; concurrent attempt => typed Busy, no partial facts. Observer can issue separate read-only backend enumeration while app is already running but cannot create Flutter controller, navigate, mutate, launch or run during a controlled process-loss checkpoint.
4. Library proof executes internally from first page to terminal and required direct same-token GetGame lookups; never export raw token/cursor values. One changed revision, duplicate, missing page, process restart, or unprovable redirect invalidates the whole attempt. A new attempt is distinct and cannot repair the original.
5. Jobs history covers all retained LibraryRefresh, including active/terminal, preexisting and Retry relations, within a single bounded consistent transaction/read. Exceeding the measured resource ceiling is BLOCKED; no new deletion or retention policy.
6. Exact typed identities may cross the local owner-private channel; shared evidence contains only aliases/digests and source/provenance, not ROM paths, raw XML, device identifiers, or credentials. Broad OS diagnostics can only be transient inputs for package-scoped sanitized facts and require separately approved command scope.
7. Cleanup failure is recorded and remediated only under separate owner authority; do not reset app state to reestablish the diagnostics default. Match diagnostics state/workload for latency calibration and candidate qualification, without changing measured thresholds without approval.
